# uv

## What it is

`uv` is a fast command-line tool for Python packaging, written in Rust by Astral. In this repository it does exactly one job: `uv pip compile` reads the dependency ranges in `pyproject.toml`, works out one exact set of versions that fits all of them, and writes it, with file hashes, to the two lock files.

## Why this repository uses it

The two lock files are generated, never typed. One command per file turns the ranges in `pyproject.toml` into exact, hashed pins, so updating a dependency is a repeatable, reviewable step.

## Where it appears

| File | What it does with uv |
| --- | --- |
| `Makefile` (the `lock` target) | runs `uv pip compile` twice |
| `requirements.lock`, `requirements-dev.lock` | the generated output |

## How it works underneath

Resolving dependencies is a puzzle: package A needs `B>=1,<3`, package C needs `B>=2`, so the answer must pick a `B` that fits both, and the same for every package below them. `uv` downloads package metadata from PyPI, solves the puzzle, and prints the result. `--universal` asks for a solution that works on every operating system and Python version in `requires-python` at once; lines that only matter on some platforms get a *marker* such as `; implementation_name != 'pypy'`. `--generate-hashes` also records the SHA-256 of every file a package could be installed from. The output is plain text in the same format `pip` reads.

`uv` is a developer tool: it is needed to re-create the lock files (`make lock`) but not to install or run the project, which uses plain `pip` and the lock files.

## Walkthrough of this repository's use

The only use of `uv` is the `lock` target:

```make
lock: ## re-resolve requirements.lock and requirements-dev.lock with hashes (needs uv)
	uv pip compile pyproject.toml --universal --generate-hashes -q -o requirements.lock
	uv pip compile pyproject.toml --universal --extra dev --generate-hashes -q -o requirements-dev.lock
```

- `lock: ## re-resolve requirements.lock and requirements-dev.lock with hashes (needs uv)`: A target with no prerequisites.
- `uv pip compile pyproject.toml --universal --generate-hashes -q -o requirements.lock`: `uv` works out exact versions for the runtime dependencies. `--universal` makes the result valid on every operating system, `--generate-hashes` records each file's hash, `-q` is quiet, `-o` names the output file.
- `uv pip compile pyproject.toml --universal --extra dev --generate-hashes -q -o requirements-dev.lock`: The same, including the `dev` group, written to `requirements-dev.lock`.

## Try it yourself

Run these from the repository folder (after `make up`).

```bash
uv --version
```

Prints the installed `uv` version (this repository does not need a specific one; the lock format is the standard `pip` format).

```bash
uv pip compile pyproject.toml --universal --generate-hashes -q -o /tmp/check.lock && diff -q requirements.lock /tmp/check.lock
```

Re-resolves into a temporary file and compares. Identical output means the lock is current; a difference means newer versions exist or the ranges changed. (Needs network access.)

## Mistakes people make

- Running `uv pip compile` without `--generate-hashes` and then installing with `--require-hashes`; pip would reject the lock.
- Forgetting `--extra dev` for the development lock. The runtime lock deliberately has no test tools.
- Updating `pyproject.toml` ranges without regenerating the locks. The Makefile's `$(STAMP)` rule depends on both so a stale venv is rebuilt, but the locks must be regenerated by hand with `make lock`.
- Treating a lock refresh as harmless. New versions can change behaviour; run `make test` and `make audit` after `make lock`.
- Expecting `uv` to install here. The Makefile installs with `pip`; `uv` only writes the locks.

## Check yourself

1. What does `uv pip compile` produce?
   *Answer:* A lock file: exact versions of all packages, with hashes.
2. What does `--universal` mean?
   *Answer:* The result is valid for all platforms and Python versions the project supports, with markers for platform-specific lines.
3. What does `--extra dev` add?
   *Answer:* The packages in the `dev` group of `[project.optional-dependencies]`.
4. Which tool installs from the lock in this repository?
   *Answer:* `pip`, with `--require-hashes`.
5. When must you run `make lock`?
   *Answer:* After changing dependency ranges in `pyproject.toml`.
