# ai-traces-to-trusted-eval-set

A pipeline that turns 1,000 raw support-assistant traces into eval set v1: scrubbed of personal data, deduplicated, twice labeled with a measured kappa, topped up with 100 filtered synthetic hard cases, and frozen with file hashes and lineage back to every trace id. Every stage is measured against an answer key the generator wrote when it planted the problems.

## Prerequisites

| Tool | Version | Used for |
| --- | --- | --- |
| Python | 3.12 or 3.13 (tested with 3.13.12; CI uses 3.13) | the pipeline and tests |
| GNU Make | 3.81 or newer | every command below |
| Python packages | `anthropic` 2.3 or newer at run time (only the real-model adapter imports it); pytest, pytest-cov, ruff, mypy, import-linter, pip-audit for development. Hash-pinned in `requirements.lock` and `requirements-dev.lock`; `make` installs them into `.venv/` | everything |
| uv | any recent version, only for `make lock` | regenerating the lock files |

No Docker, no database, no cloud account, no API key. The offline run uses a recorded-response adapter. The real adapter reads `ANTHROPIC_API_KEY` from the environment and is exercised only by `make test-live` and `make record-synthetic`.

## Setup, run, test, stop

```bash
make up                 # .env from .env.example, the .venv from the lock file, work/ and reports/
make run                # build eval-set/v1 from the committed raw traces (about 1.5 minutes), offline
make rebuild-check      # rebuild in a temp folder; the manifest must equal the committed one
make test               # unit, integration-style and end-to-end tests offline, with coverage
make lint               # ruff check, ruff format check, mypy (strict), import-linter
make check              # lint and test
make audit              # known-vulnerability check of the locked dependencies
make down               # remove work/ (it holds the raw scrub map)
```

`make help` lists every target. Single stages: `make load`, `scrub`, `dedup`, `sample`, `label`, `synthesize`, `compare`, `contamination`, `freeze` (each needs the stages before it). `make data` regenerates the raw traces and the answer key from the seed (the committed files are what it writes). Operational log lines (logfmt, no message text) go to standard error; results go to standard output and to `reports/`.

With a key (never needed for anything above):

```bash
export ANTHROPIC_API_KEY=...          # your own key; nothing in this repository stores one
make test-live                        # one real call, skipped without RUN_LIVE=1 and a key
make record-synthetic                 # replace the sample cassette with real model recordings
MODEL_ADAPTER=claude LABELER=model make run   # real synthetic cases and real model labelers
```

## The data and what stands in for what

| Piece | What it is here | What replaces it with a key or people |
| --- | --- | --- |
| Raw traces | Generated by `application/generate_traces.py` (60 intents, paraphrases, typos, multi-turn), 1,010 lines in `data/raw/traces.jsonl` | Your real traces in the same schema |
| Answer key | `data/raw/answer_key.json`, written by the generator | none; real traces have no key |
| Annotators A and B, adjudicator | `SimulatedAnnotator` (12% and 14% structured error) and `SimulatedAdjudicator`, driven by the key | `LABELER=model` (model passes and a model adjudicator) or your own `Labeler` over a sheet |
| Synthetic messages | `tests/fixtures/cassettes/synthetic-v1.json`, **authored by `scripts/author_synthetic_cassette.py` from templates**, not recorded from a model (its `provenance` says so) | `make record-synthetic` |
| The "current assistant" for synthetic cases | `application/reference_assistant.py`, a keyword matcher | your assistant behind the same function |

## Done when: the lesson's checklist and the proof for each line

Numbers are from `make run` on the committed seed (`reports/*.md`, `reports/summary.json`).

| # | Done when (from the lesson) | Command | What proves it |
| --- | --- | --- | --- |
| 1 | All 1,000 traces load, the ten extra malformed lines are rejected by line number, and the answer key is saved next to the raw file. | `make load` | [reports/01-load.md](reports/01-load.md): 1,010 raw lines, 1,000 loaded, 10 rejected, each with its line number, planted kind and the parse reason; "equal the planted malformed lines: True". The key is `data/raw/answer_key.json`. |
| 2 | The scrubber catches at least 98% of the planted values with every miss listed, and a scan of the output finds none of the planted raw values. | `make scrub` | [reports/02-scrub.md](reports/02-scrub.md): 259 of 264 caught (98.1%), 0 over-scrubbed replacements; the five misses are listed and are the deliberately hard planted forms (a spelled-out phone number twice, two spelled-out emails, a name with no cue); no non-hard planted value remains in `eval-set/v1/cases.jsonl` (`test_no_planted_raw_value_survives_in_the_eval_set`). The report also shows the first email pattern at 235 of 264 (89.0%) while its output looks equally clean. |
| 3 | Precision and recall of near-duplicate detection against the planted pairs are reported at the chosen threshold, and every dropped trace points to the trace that absorbed it. | `make dedup` | [reports/03-dedup.md](reports/03-dedup.md): a 24-row sweep (shingle size, threshold, digit guard); the textbook default (3-word shingles, 0.6) gives 33.0% precision and 75.0% recall; chosen size 2, threshold 0.7, digit guard on: precision 55.0%, recall 76.2%. Exact duplicates: 50 planted, 50 found, 0 unplanted. `work/dropped.jsonl` has dropped, kept, method and score per row. |
| 4 | The guide fits on two pages and every label has at least one example and one counter-example from the sample. | `make sample` | [eval-set/v1/labeling-guide.v1.md](eval-set/v1/labeling-guide.v1.md): 490 words; four labels, each with an example and a counter-example taken from the 300-trace sample (trace ids in the text). |
| 5 | Kappa is reported with the labelers' confusion matrix, every disagreement has a final label and a reason, and the guide changed at least once because of them. | `make label` | [reports/05-agreement.md](reports/05-agreement.md): raw agreement 75.0%, kappa 0.584, per-label kappa, confusion matrix, 75 disagreements each adjudicated with a reason (`eval-set/v1/labels.jsonl`, `decided_by: adjudicated`), [guide v2](eval-set/v1/labeling-guide.v2.md) adds the three most frequent confusions as rules. The 90%-agreement-but-kappa-0 case is built in `tests/unit/domain/test_dedup_labels_sampling.py`. The two annotators are simulated (see the table above). |
| 6 | 100 synthetic cases sit in their own slice tagged as synthetic, and none is within your near-duplicate threshold of a real case or of another synthetic one. | `make synthesize` | [reports/06-synthetic.md](reports/06-synthetic.md): 111 calls, 100 accepted, 11 rejected (5 wrong voice, 6 near-duplicate), six gaps covered; `source: synthetic` on every row; `test_no_synthetic_case_is_within_the_threshold...` compares every synthetic case with all 399 others. The cassette is authored, so the wrong-voice and near-copy replies are planted on purpose to exercise the filters. |
| 7 | A short table shows at least three measured differences, and the datasheet says what the synthetic slice may and may not be used to claim. | `make compare` | [reports/07-compare.md](reports/07-compare.md): 16.2 vs 19.3 mean words, 17.3% vocabulary overlap, intent-mix distance 0.75, 20.0% non-English, pass rate 64.3% real vs 22.0% synthetic; [DATASHEET.md](eval-set/v1/DATASHEET.md) has the "may / may not" section. |
| 8 | Rebuilding from the same traces and seed reproduces the same hashes, and the contamination check reports zero overlaps. | `make rebuild-check`, `make contamination` | `rebuild reproduces the committed manifest: 5 file hashes identical`; [reports/08-contamination.md](reports/08-contamination.md): 6 few-shot and fine-tuning texts checked, 0 overlaps (a test plants an overlap and finds it). The manifest ([eval-set/v1/manifest.json](eval-set/v1/manifest.json)) holds hashes, scrubber and dedupe versions, kappa, seed and the lineage of every case. |

No "Done when" line needs a live key. Lines 2, 5 and 6 are about the pipeline's behavior; with a key, `MODEL_ADAPTER=claude LABELER=model make run` runs the model-dependent parts for real and `make test-live` checks the adapter.

The lesson's Java twin (Spring AI for the synthetic step) is not built; see "What is simplified".

## What is simplified for teaching

- The traces, the answer key, both annotators and the adjudicator are simulated, and the synthetic messages in the cassette are authored, because no model key is available to the build. The code paths for the real model and for model labelers exist and are tested against stubs; they have not been run against a live model.
- The Java half of the lesson is not built; this is the Python half only.
- The near-duplicate detector reaches 55% precision at the best setting on this templated traffic, the same effect the lesson reports; the digit guard helps but does not remove it.
- Names are found only after cue phrases ("my name is", "thanks,"); the five misses are the planted hard forms.
- Intermediate files in `work/` include the raw values the scrubber replaced (all synthetic here). Real traces would need that folder kept private; it is git-ignored.

## Project structure

```text
src/eval_set_builder/
  domain/            traces and their schema, the scrubber and its measurement, shingles and near-duplicate
                     arithmetic, labels and kappa, sampling, synthetic rules, guide text, comparison, contamination.
                     Depends on the standard library only.
  application/       the generator, the stages (ingest, dedupe, labeling, synthetic, freeze), reports, the
                     pipeline, and the ports (TextModel, Labeler, Adjudicator, Workspace). Depends on domain.
  infrastructure/    adapters: recorded and Claude text models, simulated annotators, directory workspace,
                     settings, logfmt logging, retry, shutdown. Depends on application and domain.
  interfaces/        the `eval-set` command and the wiring. Nothing depends on it.
data/raw/            traces.jsonl (1,010 lines) and answer_key.json, written by `make data`.
prompts/             synthesize, label and adjudicate prompts as versioned files, with CHANGELOG.md.
fewshot/, finetune/  the files the contamination check compares against.
eval-set/v1/         the product: cases, labels, datasheet, both guides, manifest.
reports/             one report per stage plus summary.json.
scripts/             author_synthetic_cassette.py.
tests/
  unit/              domain, application, infrastructure, interfaces; one session-wide full run reused by many tests.
  e2e/               the lesson's Done-when lines checked on the committed data and reports.
  live/              the opt-in real-model test (skipped by default).
  fixtures/          the sample cassette (about 50 KB).
docs/adr/            decision records.
```

The dependency rule (domain depends on nothing; application on domain; infrastructure and interfaces on both; nothing on interfaces) is enforced by `make lint` through import-linter. A second contract forbids `domain` and `application` from importing `anthropic`.
